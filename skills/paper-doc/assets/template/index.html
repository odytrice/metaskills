1Start here

Clarity before completeness

The document should work at two speeds: a quick read for the decision, and a closer read for the implementation.

Orient

Say what matters

Name the audience, the problem, and the conclusion. Give the reader a reason to keep going.

Explain

Make the boundaries visible

A diagram is a view of a model. Give every box a responsibility and every arrow an intention.

Ground

Keep the evidence close

Distinguish current behavior, proposals, and examples. Cite the source instead of decorating an assumption.

A page that reads like a document

Use editorial hierarchy to make dense information approachable. Serif headings set the pace; clear body text carries the explanation; monospaced labels hold the metadata.

Keep the conclusion in the prose. Controls, diagrams, and expandable details support it.

2Reasoning

Record the tradeoff

A compact decision table makes the chosen approach and its cost visible in the same place.

Illustrative choices for a report-generation service
DecisionRationaleConsequence
Queue long-running workAn HTTP request need not wait for report generation.Expose job status and specify retry semantics.
Keep a durable job recordThe system can recover after a worker stops.Claims and completion writes need a consistency policy.
Start with pollingThe browser can retrieve status through the existing API.Choose a polling interval and account for request volume.
Explain what the choice makes easier, and what it makes harder.

Open questions

What happens after a worker crashes?
A real specification must define claim expiry, retries, and how duplicate side effects are prevented. The sample model does not prove those guarantees.
How long are source datasets retained?
Retention is intentionally unspecified in this illustrative model. A production document should cite the agreed policy.

4Put it to work

From explanation to action

Checklists and timelines are useful when they capture real completion criteria. Keep them short enough to act on.

Before sharing

A small authoring loop

01 · Understand
Read the sources and identify the reader's question.
02 · Shape
Write the conclusion and arrange the supporting sections.
03 · Model
Add only the views and flows that explain the system.
04 · Verify
Open the actual output and test what a reader will use.
